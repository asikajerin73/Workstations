## ★ 三个真实踩坑（必须写进 SDS / 新会话清单）

### 坑 1：`ELECTRON_RUN_AS_NODE=1` 会让 Electron 变成纯 Node

**现象**：`electron.exe .` 启动后，`require('electron')` 返回**字符串**（npm 包的 exe 路径），`app` 是 `undefined`，报错：
```
TypeError: Cannot read properties of undefined (reading 'whenReady')
```

**原因**：DSH 会话的 pwsh 进程环境里带着 `ELECTRON_RUN_AS_NODE=1`。该变量存在时 Electron 以纯 Node 模式运行，**不加载 Electron 运行时**，`require('electron')` 于是走普通 CommonJS 解析，拿到 npm 包里 `index.js` 导出的 exe 路径字符串。

**修法**：启动前 `Remove-Item env:ELECTRON_RUN_AS_NODE`。测试脚本、e2e、`pnpm dev` 都必须先清这个变量。

**为什么危险**：报错信息（`reading 'whenReady'`）指向 `app` 未定义，完全看不出根因是环境变量。不查 `Get-ChildItem env:` 会一直以为是 `package.json` 缺 `main` 或安装坏了。

### 坑 2：Electron 二进制必须走镜像，且 postinstall 需要 `node` 在 PATH 里

**现象 A**：`pnpm add -D electron` 报
```
node_modules/electron postinstall: 'node' is not recognized as an internal or external command
ELIFECYCLE Command failed with exit code 1.
```
**原因**：pnpm 用 `node` 这个名字 spawn postinstall 子进程，而本机 Node 装在非标准目录、当前进程 PATH 里没有它。
**修法**：执行前把 Node 目录加进 `$env:Path`。

**现象 B**：不清 `ELECTRON_MIRROR` 时 `install.js` 从官方源下载，**10 分钟无进展**。
**修法**：`$env:ELECTRON_MIRROR = "https://npmmirror.com/mirrors/electron/"`，实测 712ms 可达，180 MB 下载很快完成。

### 坑 3：`electron-rebuild` 找不到版本号

**现象**：
```
Unable to find electron's version number, either install it or specify an explicit version
```
**原因**：pnpm 的符号链接结构下，`@electron/rebuild` 定位不到 `node_modules/electron/package.json`。
**修法**：`pnpm exec electron-rebuild -f -w better-sqlite3 -v 33.4.11`（显式 `-v`）。实测 `✔ Rebuild Complete`。

## 副产品：推翻了一条旧技术结论

**`ATTACH` 上限**：连续 ATTACH 成功 **10 次**，第 11 次报 `too many attached databases - max 10`。

即 `SQLITE_MAX_ATTACHED = 10` 指的是**附加库**数量，**不含** `main` → 总连接数上限 11，插件库最多 **10** 个。

此前 SDS v1.0/v1.1 与 PLAN 都写"含 main 共 10 → 最多 9 个插件库"，是**差一错误**。已修正：
- `docs/SDS.md` CL-243 与 GAP-04
- `docs/PLAN.md` §4 数据层、ADR 第 ③ 条

**实际影响**：本设计只同时挂 3 个库，行为不变；但风险登记 R-11 与断言里的数字原本是错的。
