# T-002 仓库骨架与构建基线

> 里程碑 M3｜人日 1.5｜依赖 T-001（DONE）｜状态 **READY**
> **目标：`pnpm typecheck && pnpm test && pnpm build` 三条命令零错误**，并建立 SDS §2.0 的完整目录骨架。
> 这是第一个写业务代码的任务。**骨架错误会让后面 14 个任务全部返工**，所以本卡的 TOUCH 列表严格限定。

## 目标（可验证）

1. `pnpm install` 成功，依赖集合**精确**等于白名单（多一个少一个都失败）
2. `pnpm typecheck` 零错误
3. `pnpm lint` 零 error 零 warning
4. `pnpm test` 全绿（本任务只需 6 个纯函数单测，见 ACCEPT）
5. `pnpm build` 产出 `out/main/index.js` + `out/preload/index.js` + `out/renderer/index.html`
6. 应用能启动并显示一个空窗口（窗口内是 Shell 占位 UI）

**本任务不做的**：`pnpm package`（M3 后半段单独验）、`pnpm test:e2e`、真实插件、命令面板、数据库。

**关于 `pnpm lint:fixtures` 的口径（★ v1.1 明确，原稿自相矛盾）**：

G-1 要求八条命令全部可执行且绿，所以 `scripts/lint-fixtures.mjs` **必须在本任务建出来并能跑通**；
但 G-5 那条"`ruleId` 集合必须恰好等于 `{ARK-COLOR-1..5}`"的**实质断言属于 M6**（那时才有 `plugins/fixtures/` 下的负样本文件）。

本任务的 `lint-fixtures.mjs` 只做**结构就绪 + 显式告知**，不许静默空过：

| 情况 | 行为 |
|---|---|
| `plugins/fixtures/` 不存在 | 打印 `NO FIXTURES YET (expected at M6)`，**exit 0** |
| 目录存在但没有任何 fixture 文件 | 同上，exit 0 |
| 有 fixture 文件 | 收集所有 `ruleId`，与期望集合比对，不符则 **exit 1** 并打印差异 |

**为什么允许 exit 0**：本任务没有 fixture 是事实，不是漏检。但它必须**打印醒目提示**，让人一眼看出"这里还没在断言"，而不是伪装成"已通过"。M6 引入 fixture 后，同一份脚本自然升级为实质断言，不需要改调用方式。

**`score.ts` 的公式（★ 以 SDS CL-280 为准，下面是逐行转写）**：

```ts
// 签名：score(cmd, q): number | null
// q 先规范化：q = query.trim().toLowerCase()；空则返回 null（不过滤，全量按频率排序）

// 候选 haystacks = [title, subtitle ?? '', ...(keywords ?? [])].map(toLowerCase)
// 对每个 haystack 算 s，最终取最大值；全为 null → 不匹配，排除

let s: number | null = null;
const idx = haystack.indexOf(q);
if (idx >= 0) {
  s = 100 + Math.min(q.length, 20);   // 命中即 100 起，越长越信（上限 +20）
  if (idx === 0) s += 30;             // 前缀命中
  if (haystack === q) s += 50;        // 完全相等
} else {
  const tokens = tokenize(q);          // CL-281
  if (tokens.length > 0 && tokens.every(t => haystack.includes(t))) {
    s = 30 + tokens.length;
  } else if (isSubsequence(q, haystack)) {
    s = 10 + (matchedBytes / haystack.length) * 5;
  }
}
```

**`tokenize(s)`（CL-281）**：CJK 按**单字**切；拉丁/数字按整词切（`/[a-z0-9]+/`）；丢弃标点。返回小写数组。

**`isSubsequence(q, haystack)`**：双指针，`q` 的每个字符按序在 `haystack` 中出现即通过。

**排序键（CL-280）**：`[score desc, usageCount desc, id asc]`，`id` 用字典序字符串比较。

> ⚠️ **注意**：v1.0/v1.1 的任务卡草稿里曾写过"按位置衰减 `s -= floor(idx/10)`"，那是**错的**——SDS CL-280 没有这条规则。以本卡上面的转写为准。
